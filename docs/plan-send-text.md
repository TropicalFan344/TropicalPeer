# 傳文字設計草稿

配對過的裝置之間可以互傳一小段文字：網址、地址、驗證碼、剪貼簿內容，或者一句話。
它是一次性的傳送，跟傳檔一樣：對方在線就立刻送到，不在線就告訴使用者。
**不是聊天**：沒有對話串、沒有離線排隊、沒有推播、不另外保存紀錄。

## 協定

傳文字是一次性的請求，跟現在的 `Resume` / `Cancel` / `Unpaired` 一樣：
開一條控制串流、送一個 `Hello`、等一個 `JoinAck`，然後掛斷。
不需要 `Offer`、檔案串流或 `FileResult`。

```go
// protocol/messages.go
type Hello struct {
	...
	// Text 是一段給使用者看的文字。對方用 JoinAck 回答：
	// OK 表示已經顯示，OK=false 表示被拒絕（Error 可能是空字串）。
	Text *Text `json:"text,omitempty"`
}

type Text struct {
	ID   string `json:"id"`   // 隨機 128 位元，hex；拿來去重
	Body string `json:"body"` // UTF-8，最多 MaxTextBytes
}

const MaxTextBytes = 32 << 10 // 32 KB
```

```
  發送端                                    接收端
    │── 控制串流：Hello{Text} ─────────────────▶│  規則：封鎖 → 拒絕
    │                                          │        其他 → 檢查、去重、顯示
    │◀──────────────────────── JoinAck ────────│
    └─ 掛斷
```

- 發送端走 `node.ask`，跟 `RequestResume` 一樣：先連線（直連、預測連接埠、中繼、TURN，都沿用現有邏輯），送出後就關閉連線。
- 接收端在 `handleIncoming` 裡處理，位置在 `Hello.Resume` 那段旁邊，呼叫新的事件 `OnText(peer, text) (ok bool, reason string)`。
- `transfer.AcceptControl` 判斷「空的 Hello」那一行要把 `Text` 加進去。

### 去重
`JoinAck` 在途中遺失時，發送端重試會送出同一個 `ID`。接收端記住每個裝置最近收到的 200 個 ID（只存在記憶體），重複的直接回 `OK` 但不再顯示一次。

### 限制（接收端都要檢查，不能相信發送端）
- `Body` 超過 32 KB，或不是合法的 UTF-8 → 拒絕。
- 去掉控制字元，只保留 `\n` 和 `\t`。
- **去掉雙向文字的控制字元**（U+202A–U+202E、U+2066–U+2069）。不去掉的話，可以讓 `https://evil.com/moc.knab` 看起來像另一個網址。
- 去掉前後空白之後是空的 → 拒絕。
- 頻率限制：每個裝置每分鐘最多 30 則，超過的回 `OK=false`，不顯示也不通知。這是為了防止配對過的裝置用通知洗版。

### 接收規則
沿用每個裝置現有的規則，不新增設定：

| 規則 | 傳文字 |
|---|---|
| 先詢問（預設） | 直接顯示（見「待決定 1」） |
| 自動接受 | 直接顯示 |
| 封鎖 | 拒絕，`OK=false`、不附原因，跟傳檔一樣不讓對方知道被封鎖 |

文字不會寫進磁碟，也不會自動做任何事（不自動開網址、不自動寫進剪貼簿），所以直接顯示並不違背「接收端保有控制權」。
「先詢問」是為了檔案會佔空間、會落在磁碟上而設計的；文字如果也要先接受才能看，就等於多按一次。

### 舊版 App
舊版收到 `Hello{Text}`，會把它當成空的 Hello：`AcceptControl` 回錯誤、串流取消、連線以代碼 0 關閉。
發送端在等 `JoinAck` 的時候會看到串流被取消或連線被關閉。

- 這版：`ask` 在**已經送出 Hello、還沒收到 JoinAck** 時，如果遇到對方以應用程式代碼 0 關閉連線、或串流被重設，就回傳 `OutdatedError`，介面顯示「Moon Laptop 的 TropicalPeer 版本太舊，請更新後再傳。」
  其他錯誤（逾時、斷線）照舊顯示「不在線」或「傳送失敗」。
- 同時改掉「空的 Hello」這個判斷，讓**新版之後**遇到不認得的 Hello 都回 `JoinAck{OK:false, Error:"unsupported"}`，不再直接斷線。以後再加新功能，就能清楚分辨「對方太舊」。

## 引擎（appcore）

```go
// 送出一段文字，對方顯示了才回傳。錯誤已經寫成給人看的句子
// （不在線、被拒絕、版本太舊、太長…）。
func (c *Core) SendText(peerID, body string) (TextDTO, error)
func (c *Core) ListTexts() []TextDTO   // 新的在前
func (c *Core) MarkTextRead(id string) // 複製或關閉之後

// 事件 "text:new"（收到或送出）、"text:update"（已讀）：
// { id, peerId, peerName, direction, body, at, unread, relayed }
```

- 收到的文字放在 `Core` 的記憶體裡，最多 50 則，關閉 App 就消失。
- 發送端在傳送中、或接收端還有**未讀**文字的時候，`busy()` 回 true。這樣 App 自動更新重啟時，不會把使用者還沒看到的文字弄丟。
- 傳送中顯示「正在傳送…」，連線沿用傳檔時的逾時設定。

## 桌面介面

### 傳送（2026-11-10 改版）

**電腦：** 裝置卡片可以展開一條輸入列。展開方式：滑鼠移過去出現的 💬、按右鍵，或在卡片上按 Ctrl+V（貼上的內容先填好，按了才送）。
- ➤ 或 Enter：只傳文字（Shift+Enter 換行，輸入法選字中不算）。Esc 收起。
- 📎：選檔案，檔案帶著這段話一起傳。輸入列有字時，把檔案拖到卡片上，或直接點卡片選檔案，也會帶上這段話。
- 收起時，卡片的行為跟以前一樣。

**手機：** 點裝置卡片出現的選擇畫面，下面多一條輸入列和 ➤。
- 有字的時候，按上面的「照片／檔案／資料夾」就附上這段話；按 ➤ 只傳文字。
- 文字框不會自動聚焦；從選單的「傳送文字」打開時才會。

傳送失敗時，錯誤顯示在輸入列下面，文字留著。

### 附言（跟檔案一起送的一段話）
- `Offer.Note`，上限 4 KB（`protocol.MaxNoteBytes`），接收端用跟文字一樣的方式清理。
- 新版接收端接受邀請時回 `Response.NoteShown`。如果有附言卻沒收到這個回報，表示對方是舊版：
  檔案照樣送到，發送端會提示「對方版本太舊，看不到附言」（`TransferDTO.NoteLost`）。
- 接收端：邀請上直接顯示附言（幫助決定要不要收），收到的提示、系統通知和傳輸列也都有，傳輸列可以複製。
- 從其他 App 分享文字（Android）時用的「傳送這段文字」畫面保留。

### 接收
- 顯示在現有的 `OfferStrip` 那一排（收到檔案邀請的地方，排在邀請下面），但是是另一種卡片，顏色比邀請安靜：
  裝置名稱、時間、文字內容（超過 6 行就收合，可以展開），以及「**複製**」和「關閉」兩個按鈕。
  最多顯示最新的 3 則，更多的話顯示「還有 N 則文字在『傳輸』頁」。
- 內容裡的網址（只認 `http://` 和 `https://`）變成連結，按下去用系統瀏覽器開啟（Wails `BrowserOpenURL`；Android 用 Intent）。
  不顯示網頁預覽，也不自動開啟。
- 傳輸頁面的清單裡也列出收到和送出的文字，用 `TransferRow` 的另一種樣式，同樣有「複製」按鈕。

**安全規定：** 文字一律用 Svelte 預設的跳脫輸出，**不准用 `{@html}`**（目前專案裡沒有用到，要繼續保持）。
網址變連結要在程式裡把文字切成「純文字」和「連結」兩種片段，各自輸出，不能先拼成 HTML 字串。

### 通知
- App 不在畫面上時，用現有的系統通知：標題「Moon Laptop 傳來文字」，內容是前 100 個字，有「複製」按鈕。
- 點通知會開啟 App，文字在最上面那一排。

## Android

- **分享選單：** 現在從其他 App 分享文字（沒有附檔案）時，`handleShare` 會把它包成一個小的 `.txt` 檔來傳。
  改成：只有文字的時候就用傳文字，選好裝置就送出。文字超過 32 KB 時，還是照舊當成 `.txt` 檔傳。
- **通知：** 新的 `texts` 頻道，通知上有「複製」按鈕（`TextActionReceiver`）。
  鎖定畫面上用 `setPublicVersion` 只顯示「Moon Laptop 傳來文字」，不顯示內容，因為內容可能是驗證碼或密碼。
- **背景：** 跟收檔案一樣，要開啟「保持可接收」才收得到。

## tpcli

```
tpcli send-text <裝置> <文字>        # 或從 stdin 讀：echo hi | tpcli send-text <裝置> -
```
`tpcli` 收到文字時直接印出來。這也方便做整合測試。

## 語言

新的字串放進 `locales/*.json`，10 種語言都要有：按鈕（傳文字、複製、已複製）、對話框標題和提示、
「已傳給 {name}」、「{name} 傳來文字」、「版本太舊」、「文字太長」、傳輸清單的標籤、Android 頻道名稱。

## 測試

- `transfer`：Hello{Text} 一來一回；超過大小、非 UTF-8、只有空白、雙向控制字元都被擋下。
- `node`：封鎖的裝置得到 `OK=false`；同一個 ID 只顯示一次；頻率限制。（經過中繼：走的是跟傳檔一樣的 `connect`，沒有另外寫測試。）
- **舊版相容：** 用一個「不認得 Text」的假接收端（模擬 0.2.4 的 `AcceptControl`），確認發送端拿到 `ErrPeerOutdated`，而不是「不在線」。
- `appcore`：有未讀文字時 `busy()` 為 true；50 則的上限。
- 前端：內容含 `<img src=x onerror=…>`、`javascript:` 網址時，原樣顯示成文字，不會變成連結或被執行。
- 實機：電腦 ↔ Mac ↔ Android，兩台在不同網路，走直連和 TURN 各一次；Android 分享選單分享網址。

## 決定（2026-11-10，照建議）

1. **「先詢問」的裝置傳來的文字不用先問**：直接顯示，被封鎖的才拒絕。
2. **紀錄不在重啟後保留**（只在記憶體）。
3. **Android 新增 `texts` 通知頻道**，使用者可以分開關閉文字通知。
4. **大小上限 32 KB**；更長的內容用 `.txt` 檔傳。
